# T-AB-05 brief: S1 archaeology through the Atlassian route, and the dry-run walk to `clarifying`

## What this delivers

`factory/scripts/tools/archaeology`, a standalone script that runs
`git blame --line-porcelain` over every touched-area candidate that is not
self-evident, extracts the issue keys its commits' full messages name with
one regex, and reads each issue through the loopback proxy's route
contract (`POST <proxy>/routes/atlassian_read`, `{"method": "issue.get",
"params": {"key": ...}}`), classifying each candidate `explained`,
`unexplained`, or `contradictory`. `runner/stages/S1.py` runs the script as
a subprocess launch under the agent sandbox profile for stage `S1` (the
same OS-enforced boundary a real agent invocation crosses), stages the
worktree and the script into that launch's own `tmp/` first since neither
`factory/` nor (outside S4) the ticket's own worktree is readable from
inside that profile, and overwrites the brief's `History` section from the
script's own output -- the classification is the runner's, never the
agent's, the same rule `Final tier` already follows. `factory/config/
sandbox.yaml` gains `endpoints.atlassian_read` and `atlassian_read` in
`proxy_allowlist.S1` only. `factory/rubrics/S1.md` gains R-S1-4's
grader-only line for non-obvious coverage, hand-written (see "Owner
decisions" below), and `runner/tests/test_s3_checklist.py`'s pinned
checklist fixture is extended for the new instance that line adds to
every ticket's expected set.

Row covered: R-S1-4 (script test for the classification, grader for
non-obvious coverage).

## Owner decisions this ticket follows

- **No real pilot repository, Jira key, or Atlassian server exists yet.**
  Every dry-run criterion is a test over a seeded git repository with a
  fake proxy standing in for the real one, plus a loud skip naming the
  missing real piece (mirroring `test_s0.py`'s own dry-run test).
- **Rubrics stay hand-written tables.** `factory/rubrics/S1.md`'s new
  R-S1-4 line is added by hand, not generated by a `rubric_gen` script --
  none exists in this codebase and this ticket does not build one.

## Design decisions this ticket makes (the brief left these open)

- **`self_evident` has no source in the brief's own schema.** The
  `Touched area candidates` table carries only `path` and `reason`
  (`runner.artefacts.BRIEF_TABLES`); the driver treats every candidate as
  not self-evident, so archaeology always runs. The script itself still
  honours `self_evident: true` when a candidate carries it (proven by its
  own tests), since a future ticket may add a real per-row signal.
- **One archaeology method, not two.** The ticket text offers `git blame`
  or a `git log` fallback "when no symbol range is given" and asks to
  "keep one method and say which." This script always runs
  `git blame --line-porcelain` over the whole file; a candidate's
  `symbol` narrows nothing (no source-level symbol-to-line-range resolver
  exists here) and only threads through to the rendered `path#symbol`.
- **The classification rule is field-based, not semantic.** "Every named
  issue resolved and its summary consistent with the change" cannot be
  judged by a script without NLP; the rule instead reads two closed
  fields the issue payload carries: `resolution` in `{"Won't Do",
  "Duplicate"}` is `contradictory`, every named issue's `status` in
  `{"Done", "Resolved", "Closed"}` is `explained`, anything else
  (unresolved, or every read failed) is `unexplained`.
- **`--proxy` is optional, defaulting from `FACTORY_PROXY_PORT`.** The
  ticket's own CLI example always shows `--proxy` given, but the S1
  driver cannot know the launcher's chosen port before the launch starts
  it -- the script reads it from its own sandboxed environment instead,
  the same way `HTTPS_PROXY`/`HTTP_PROXY` already do for every launch.
  `--proxy` still exists so a test (or the eval harness) can point the
  script at its own stand-in server.
- **T-AB-03's `routes=` parameter does not exist yet.** This ticket runs
  in parallel with it. `S1.run`'s archaeology launch calls
  `launcher.launch` with the parameters that exist today; once T-AB-03
  lands, wiring `routes=` at that one call site is a small follow-up --
  until then, a real (not test-overridden) launch's internally started
  proxy has no route dispatch, so a real Atlassian read does not work in
  production yet. Every test here bypasses this by pointing `--proxy`
  explicitly at its own local `http.server`, which a sandboxed child can
  always reach since the agent profile's network rule admits loopback
  traffic generally, not only the launcher's own assigned port.
