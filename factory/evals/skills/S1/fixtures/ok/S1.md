# Gather context, step by step

1. Read `locations.json`; open every path under `inputs`, in order.
2. Read the ticket source artefact and every context-index entry it names,
   using the `codegraph-lookup` shared skill before grepping the checkout
   by hand.
3. Walk the checkout for the ticket's touched-area candidates; list each
   with why it looks touched.
4. For each candidate that is not self-evident, run blame, then read the
   commit messages it points at for a referenced issue; classify
   `explained`, `unexplained`, or `contradictory`.
5. For every outbound dependency in `pom.xml`, resolve it against
   `factory/config/artifact-to-service.yaml`: `authoritative` when the
   mapping names the service at an exact version, `partial` when the
   package is known but the mapping is stale or ambiguous, `unknown`
   otherwise.
6. For inbound consumers, read the context index for a `caller` entry
   naming this service; if none exists or it is stale, write "callers
   unknown" rather than guessing.
7. Grep the touched path for flag reads; list each with its reference.
   Never look up a flag's current value anywhere.
8. Write `out/brief.md` with the fixed sections in the fixed order: Ticket
   summary; Linked sources; Touched area candidates; History; Impact
   evidence; Flags; Blind spots; Unknowns; Index entries used; Final tier;
   Pilot-exclusion recheck; Blockers. See the agent file for what each
   section requires.
9. Leave "Index entries used" and "Final tier" empty; the runner fills
   them.
10. If a fact you need would change ticket eligibility or a public
    contract and no source answers it, write it to Blockers with what you
    tried; otherwise put it in Unknowns and continue.
