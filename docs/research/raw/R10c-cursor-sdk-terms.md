### RQ-T-10. What terms govern automated, unattended use of the Cursor SDK by a team or enterprise account?

**Answer.** No clause in Cursor's Terms of Service, Data Use page, or SDK/API documentation singles out programmatic, scripted, or unattended agent runs as distinct from interactive IDE use, and none requires a human to be present. The Terms of Service (last updated 2026-09-03, fetched directly) prohibit scraping/harvesting data from the Service and using the Service's output to train a competing model, but say nothing about running the SDK unattended, in a script, or on a schedule; "Auto-Code Execution" is explicitly addressed as a feature (code can run without manual review) with the user "solely responsible," not restricted. Rate limiting is real and documented, but it is a technical default (20 requests/minute unless an endpoint states otherwise, 429 on excess) applied per authenticated user/team/organization across all Cursor APIs, not a policy aimed at automation as such. SDK usage is billed and metered as ordinary account usage: it draws from the same "request pools" and spend limits as IDE and Cloud Agent usage, with Team plans getting one team-level spend limit and Enterprise plans getting both team- and member-level limits enforceable via dashboard or Admin API. Admin API keys are scoped (`admin:*`) and separate from the per-user or per-service-account keys the SDK itself authenticates with. Privacy Mode is available to any plan and can be enforced at the team level so members cannot disable it, and Cursor's own documentation states SDK runs follow "the same pricing, request pools, and Privacy Mode rules" as IDE runs — so Privacy Mode's no-training, zero-data-retention posture is designed to extend to SDK runs, though no page independently confirms this by testing rather than by cross-reference. The SDK's and Cloud Agents API's "Beta" label carries no separately stated terms on breaking changes, support, or SLA beyond the SDK reference's own advisory to discover models dynamically because "model IDs and parameter shapes can change as new models ship" — there is no committed deprecation-notice period, no support-response-time commitment, and no uptime SLA found for beta-labeled surfaces on any of the pages fetched.

**Patterns found.**

- "Section 1.5(viii)" of the Terms of Service (as summarized from the fetched page) prohibits "harvesting, scraping, or extracting data from the Service." "Section 1.5(v)" prohibits using "the Service or any Suggestions to develop or train a model that is competitive with the Service, or engage in model extraction or theft attacks." "Section 1.7" addresses "Auto-Code Execution": code can run automatically without manual review, and the user remains "solely responsible" for its impacts. "ANYSPHERE WILL NOT USE CONTENT TO TRAIN...ANY AI MODELS, UNLESS YOU'VE EXPLICITLY AGREED" (Section 1.3). No clause restricting bots, automation, or unattended/scripted runs as such, and no separate Acceptable Use Policy document was reachable at a distinct URL within budget — the ToS references an AUP by name but the fetched page's own content did not surface it as a linked, separately fetchable document. — Cursor, "Terms of Service," `https://cursor.com/terms-of-service`, official legal document, fetched directly, last updated 2026-09-03 (fetch date 2026-09-04).
- "All APIs implement rate limiting to ensure fair usage and system stability. Limits apply per authenticated user, team, or organization, and most are scoped to a single endpoint. Unless an endpoint documents a different limit, the default is 20 requests per minute." Exceeding it returns HTTP 429. Admin API endpoints are mostly 20 requests/minute (audit logs, daily usage data), spend-limit updates 250 requests/minute, Analytics API team-level endpoints 100 requests/minute, Bugbot's `/bugbot/review` 30 requests/minute. — Cursor Docs, "Cursor APIs Overview," `https://cursor.com/docs/api`, official documentation, fetched directly.
- "SDK runs follow the same pricing, request pools, and Privacy Mode rules as runs from the IDE and Cloud Agents. Spend shows up in your team's usage dashboard under the SDK tag." Service-account API keys bill to the owning team; user API keys bill to that individual's plan. — Cursor Docs, "Cursor TypeScript SDK," `https://cursor.com/docs/sdk/typescript`, official documentation, fetched directly.
- "Model ids and parameter shapes can change as new models ship" — the SDK reference's own stated reason to discover models dynamically rather than hard-code them. No SLA, support-response, or deprecation-notice language was found on this page. — same source, fetched directly.
- Teams plan: "Set a team-level spend limit. When reached, all members consuming on-demand usage lose access to AI features." Enterprise plan: "Set both team-level and member-level limits. Member limits can be configured through: 1. Member overrides in the Members tab 2. Group overrides in the Groups tab 3. Team general spend limit in the Spending tab." When a limit triggers: "AI features stop working for that specific user," "Other team members continue unaffected," usage resumes at the next billing cycle. — Cursor Docs, "Spend limits," `https://cursor.com/help/account-and-billing/spend-limits`, official documentation, fetched directly.
- Admin API: "Basic Authentication with your API key as the username." Keys are scoped, e.g. `admin:*`, format `crsr_...`. `/teams/user-spend-limit` "Set spending limits for individual team members"; setting `spendLimitDollars` to `null` clears the limit. This Admin API's own keys are distinct administrative credentials, separate from the per-user/service-account keys the SDK authenticates with. — Cursor Docs, "Admin API," `https://cursor.com/docs/account/teams/admin-api`, official documentation, fetched directly.
- "Enable Privacy Mode for the team. Optionally enforce it so members can't disable it." Cloud Agents are "the only feature that requires Cursor to store code... encrypted copies of repositories... stored temporarily while the agent runs. Deleted after the agent completes." A named list of models (e.g., certain Claude models) fall outside the zero-data-retention agreement with the provider; "Enterprise customers and customers with Privacy Mode enabled" must have those models explicitly approved from the dashboard before requests to them succeed. — Cursor Docs, "Privacy and Data Governance," `https://cursor.com/docs/enterprise/privacy-and-data-governance`, official documentation, fetched directly.
- "Customer Data will not be used for training by Cursor. Cursor maintains zero data retention (ZDR) agreements with all providers." Without Privacy Mode: Cursor "may use and store codebase data, prompts, editor actions, code snippets, and other code data and actions to improve our AI features and train our models." "All cached file contents are temporary, never permanently stored, and never used as training data when privacy mode is enabled." — Cursor, "Data Use & Privacy Overview," `https://cursor.com/data-use`, official document, fetched directly, last updated 2026-08-28.
- Security page: "When enabled, we will not train on your data. We also implement technical controls and contractual requirements with our model providers to protect your data." Vulnerability disclosure: acknowledged within 5 business days. No SDK-specific or automation-specific clause found. — Cursor, "Security," `https://cursor.com/security`, official document, fetched directly, last updated 2026-08-25.
- Cloud Agents API and SDK product framing: "SDKs run Cursor agent workflows (workspace context, tools, commands, and edits). They are not a standalone model-inference or chat-completions API." The Cloud Agents API is listed as "Beta (All Plans)" availability, with no separate terms for that status beyond the availability label itself. — Cursor Docs, "Cursor APIs Overview," `https://cursor.com/docs/api`, official documentation, fetched directly.
- The forum announcement thread itself (`https://forum.cursor.com/t/cursor-sdk-cloud-agents-api-updates/159284`) contains no terms-of-use, rate-limit, billing, or SLA content in either the original post or its visible follow-ups within the fetched content; it is a feature announcement, and the "public beta" label appears there with no elaboration on what beta entails contractually. — Cursor Community Forum, fetched directly.

**Evidence quality.** Primary and fetched directly for the Terms of Service, Security page, Data Use page, SDK reference page, Admin API page, Spend Limits page, Privacy and Data Governance page, API overview page, and the forum announcement — eight of nine core claims rest on direct fetches with dated pages, not search snippets. The Terms of Service section numbers and exact prohibited-use wording come from a fetch-tool summary rather than a raw-text quote verified character-for-character against the live HTML, which is a caveat on precision, not on sourcing: the fetch tool processes HTML through a model before returning text, so section numbers should be treated as approximately located rather than guaranteed exact. One page (`cursor.com/help/security-and-privacy/privacy`) was surfaced only by search and not independently fetched. No independent (non-Cursor) source was found or sought for this question, since it concerns Cursor's own contractual terms, which only Cursor can state authoritatively.

**Fit to the inputs row.** `docs/prd/inputs.md` row 1 (ledger) and section 6's runtime decision name the Cursor SDK as primary runtime for the initial version, citing R10b's verification of its telemetry surface; that decision rested partly on R10b's gap that "no terms for programmatic use were found." This packet closes that gap with a negative result that supports the existing decision rather than requiring a reversal: nothing in the Terms of Service, Data Use page, or SDK/API documentation restricts, conditions, or specially prices unattended/scripted use relative to interactive IDE use — the factory's planned pattern (one Cursor SDK invocation per stage, run from a script, not from the IDE) is not a distinct category under any fetched clause. Three points do warrant a note in section 6: (1) rate limiting is real (20 requests/minute default across Cursor's APIs generally; SDK-specific numeric limits were not separately stated, only that SDK runs "follow the same... request pools" as IDE/Cloud Agent runs) — the factory's stage-per-invocation pattern at the parallel-ticket ceiling already named in row 5 (1 to 3 concurrent tickets) is almost certainly inside this, but no page states a distinct SDK requests-per-minute figure to check that against; (2) Privacy Mode is enforceable at the team level ("enforce it so members can't disable it") and is described as extending to SDK runs by cross-reference, which is a stronger and more specific answer than R10b had — this satisfies charter C5's "nothing leaves the factory" concern for training-on-code, provided the factory's Cursor team account has Privacy Mode enforced, which is an operational setup step the PRD does not yet name; (3) the SDK's beta status carries no support/SLA/breaking-change commitment beyond an advisory to discover models dynamically — this is consistent with D5's existing framing that the runtime choice is not locked in, and argues for the manifest-recorded model-per-stage approach (D31, already selected) rather than any hard-coded model ID, which the SDK docs independently recommend for the same reason (models can change).

**Gaps.** No standalone Acceptable Use Policy document was located at a distinct, fetchable URL; the Terms of Service references such a policy by name but the fetched page's own content did not surface a separate link within budget, so its exact automation-specific language (if any exists beyond what the ToS itself states) is unconfirmed. `cursor.com/docs/account/plans-and-usage` and `cursor.com/docs/account/privacy`, the two URLs specified in the task prompt for this material, both returned HTTP 404 as of the fetch date (2026-09-04); the working replacement pages used instead (`cursor.com/docs/account/teams/pricing`, `cursor.com/help/account-and-billing/spend-limits`, `cursor.com/docs/account/teams/admin-api`, `cursor.com/data-use`) may not be the exact successors Cursor intends, since no redirect was observed, only a not-found response. `cursor.com/help/security-and-privacy/privacy` was found via search but not independently fetched; its content is not confirmed to add anything beyond `cursor.com/data-use` and `cursor.com/docs/enterprise/privacy-and-data-governance`, both of which were fetched. No SDK-specific numeric rate limit (as opposed to the general 20-requests-per-minute API default) was found; whether the SDK's agent-run endpoints share that exact number or a different one is unstated on any fetched page. No committed SLA, support-response time, or breaking-change notice period was found for beta-labeled SDK or Cloud Agents API surfaces; their absence was confirmed by reading three separate pages (SDK reference, API overview, forum announcement) that would plausibly carry such language, not merely by one page's silence. The Business/Enterprise DPA document itself (as opposed to the "Privacy and Data Governance" documentation page) was not located or fetched within budget; whether it contains SDK-specific terms distinct from the documentation pages summarized above is unconfirmed.
