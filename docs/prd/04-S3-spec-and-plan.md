# S3 Spec and plan

Section 4 of the [Software Factory PRD](prd.md), one file per stage. The index holds the version, the reading rules, the rubric-line conventions, and the map from section numbers to files.

**Produces.** `plan`, one file, sections in this order: intent and scrutiny; readiness table (R-S3-21); risk map; goals/non-goals; approach; alternatives; scope and discretion; dependencies; archaeology and characterization tests; abstraction and separate debt; declared source and behavioral contracts; temporary semantic-contract checklist; task graph with typed validation recipes; test strategy; human-executed rollout; size; impact evidence and blind spots; assumptions; unknowns; required approvers. The fixed tables are readiness, scope, dependencies, contracts, tasks, tests, and size; scripts read tables, not prose. S3 approval covers the criteria version and this plan together.

**Human touchpoint.** Approve or redirect, once from each required reviewer; an ordinary Initial ticket has one. This is the first of the two structural gates. The plan is read from the first page; each reviewer should be able to decide from intent, scrutiny, the readiness table, and the risk map, and open the rest only when those raise a doubt. A redirect, to `planning` or to an earlier stage, records a `send_back` tag with a ground from `checklists/send-back-grounds.md`: duplicates existing work; technically unsound; missing backward-compatibility or migration analysis; contradicts a stated non-goal; built on a wrong brief or wrong criteria, naming the target stage; other, with a note (R-T-6).
