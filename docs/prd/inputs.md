## 1. Rules for this file

- Every row names the stage it serves and the charter items it cites. A row with no citation is removed, not kept "in case".
- "Candidate" means a category with one or two examples that have not been verified for this environment. Selections are recorded in section 6, each marked as decided by the user or recommended and standing unless vetoed.
- Enterprise rules set 2026-09-04: no niche tools, and no third-party MCP servers. First-party servers in use: GitHub, Atlassian (Jira, Confluence), AWS, Slack.
- MVP means the initial version as scoped in D20, amended 2026-09-04: S0 to S4 automated, the deterministic S5 scripts on the branch diff, the S6 review packet, and the pull request opened on approval. Everything after the pull request is Later, after the planning rubrics have survived real tickets.
- Per D5, no candidate may depend on a specific agent runtime. Per D25, nothing here touches production systems.

## 2. The three tendencies, mapped

| Tendency named | Catalogue entry | Where it is caught | Mitigation in the charter |
|---|---|---|---|
| Hallucinates dependencies | FM-20 | S5 blocking tier | Deterministic resolution of every import and version against the real lockfile and environment before any advisory pass runs (D16, D20) |
| Misses context across a large codebase | FM-14, FM-03, FM-02 | S1, S3 | Context index with last-verified dates (C3); repo history of the touched area in the brief; P5 not-touching default; a code graph or symbol index reduces the cost of finding what exists (row 3) |
| Loses state over long tasks | FM-21, FM-19 | S4 | Stateless stages that read and write only the ticket record (C3, C7); bounded attempts and a budget per tier (D14); the ledger in C5 makes repeated or skipped work visible |

## 4. Research packet R10, when the PRD reaches these rows

Answered 2026-09-04 by the `web-researcher` agent in one packet with one verification pass; findings by row are in section 5. No candidate is selected. Good-answer criteria and starting sources are in `docs/research/questions.md`, section "Tooling (PRD inputs, packet R10)". Output: `docs/research/raw/R10-tooling.md`.

- **RQ-T-1.** Which OpenTelemetry GenAI span conventions are stable enough to borrow as a ledger schema, and which of Cursor SDK, Cursor CLI, and Claude CLI expose per-invocation tool-call and token data locally without an exporter.
- **RQ-T-2.** Which open-source code graph or symbol index tools are maintained, support the languages of the pilot service, expose an MCP server, and can be invalidated on merge.
- **RQ-T-3.** What a minimal durable workflow engine costs to run on one machine, and at what number of concurrent tickets a SQLite state table is known to fail.
- **RQ-T-4.** Which git-backed or local issue trackers built for agents exist, and whether any has evidence of use beyond its author.
- **RQ-T-5.** How existing factories record agent cost per unit of work, and whether any publishes its schema.
- **RQ-T-6.** Which open-source eval harnesses support single-dimension graders, fixtures from recorded runs, and a model-separation rule, and how teams version evals next to prompts and skills.
- **RQ-T-7.** What the GitHub MCP server exposes for check runs and job logs, and what it does not.
