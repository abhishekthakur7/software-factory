# S7 PR checks and merge

Section 4 of the [Software Factory PRD](prd.md), one file per stage. The index holds the version, the reading rules, the rubric-line conventions, and the map from section numbers to files.

S7 automation is Later in its entirety (D20). Initial ends agent and check automation at the draft pull request, but R-H-11 manually records its eventual outcome so safety results are not silently lost. These rows replace that manual step with read-only observation; they do not grant merge authority.

| # | Requirement | Cites | Version | Verified by |
|---|---|---|---|---|
| R-S7-1 | Each poll records PR state, observed PR-head and target-base or merge-group SHAs, and every triggered check state (`queued`, `in_progress`, `pass`, `fail`, `cancelled`, `skipped`) through the GitHub MCP server. GitHub check results bind the observed external head and reference the latest review tuple only when that head matches it. Results and state are summarised in `pr_checks_summary`; any red or incomplete required set leaves one immutable `red_check` item whose displayed state is derived from the latest bound check rows and whose actions are wait, send back, or abandon. | D25, P7, FM-10, FM-25 | Later | Mixed-result, head-binding, immutable-item deduplication, and action tests |
| R-S7-2 | For a failed run, the factory fetches the job log and writes a summary of the likely cause with the log lines it rests on, into `pr_checks_summary`, at Light budget. It never re-runs, approves, merges, or treats a cancelled/skipped required check as green (R-I-11). | D4, D25, P7, FM-10 | Later | Failed, cancelled, skipped, and permission-denied fixtures |
| R-S7-3 | The pull request is left open for the human and polled at the section 8 cadence. A closed-unmerged PR stops polling and queues mandatory human outcome/failure-mode classification before `abandoned`; a detected human merge always moves to `merged` and records actual head, base, body, merge SHA, check disposition and production-coverage record, even when those facts also expose a control defect. Later production incident events and dispositions append independently. | D4, D25, P10, FM-18, FM-25 | Later | Open, closed-unmerged, clean merge, exposure/coverage, and mismatched-merge tests |
| R-S7-4 | On every observation, the runner compares the remote PR head and target-base parent with the latest approved bindings; a raw merge-group SHA is recorded separately and does not itself invalidate the plan. Branch movement before merge records the mechanical observation, invalidates final approval, and queues mandatory human failure-mode classification. A trusted `sync_pr_head` fetches the exact remote SHA, preserves conflicting local work, registers the imported revision, and returns through S4 for a fresh deviation set before S5; it never jumps directly to checks. Target-base-parent movement invalidates the plan binding and permits only recorded refresh, send-back, or abandon. If merge already occurred, reality is recorded immediately and any stale head/base/body/approval or non-green required check becomes an unresolved FM-25 `control_defect` tag and control-defect event rather than a backward transition. | D21, P10, FM-18, FM-25 | Later | Branch sync, base-parent, merge-group, race-after-merge, human-classification, and tagged-control-defect tests |
| R-S7-5 | At close, one optional survey question is queued as a `close_survey` item (charter section 8, FM-09): how many tickets the engineer held in parallel and whether returning to this one cost effort. Skipping is allowed and recorded. Arrives with the parallel limit rising above 1. | P1, FM-09 | Later | Script test |
