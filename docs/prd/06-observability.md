**Measure computations.** Factory-performance views accept a `manifest_hash` filter and report which factory versions the window spans. Baseline views use their own definition/cohort hashes and require no pre-factory manifest. Rows below the charter section 8 set are factory-operational context, reported only in the context block (R-O-5) and never available to a scorer or proposal (C8, R-O-12).

| Measure | Computation |
|---|---|
| Revisions per ticket after plan approval, by failure mode | Count of `revision_after_approval` tags per ticket, grouped by `fm_id` |
| Questions surfaced per ticket, by tier | Count of `question` rows per ticket, by the tier on the question's `queue_item` |
| Share shown with a default | Questions with `default_option` not null, over all questions |
| Share where the default was accepted when shown | Immutable `answer.resolution_kind = default_accepted` events over question versions shown with a default; a later superseding answer does not erase the event |
| Queue latency at S2, S3, S6, by tier | Per ticket and stage, the union of open intervals for questions, plan approval, and packet approval; a batch counts once. Labeled queue latency, not attention |
| Active attention at S3 and S6, by tier and outcome | Distribution of the human-entered bucket on plan/review `approval_record` rows, including every required reviewer and `unknown`; never derived from queue latency |
| Share of generated tests kept after review | `generated_test` identities with a final `kept` decision over all generated-test identities judged by a review subject. Zero-generated-test tickets are not applicable, not 1. Later may add survival-at-merge without changing origin attribution |
| Share of plans approved without redirect | Tickets whose first canonical plan-approval subject reached quorum with no reject/redirect record or subject-bound send-back, over tickets whose first plan subject reached a decision; later plan subjects do not rewrite the first-pass outcome |
| Production incidents attributable to factory changes | Count immutable `production_incident_event` roots whose current disposition says `attributable`, by severity and disposition. Separately report every merged ticket's latest production-coverage status, exposure source/start and `observed_through`. Report zero only when every merged ticket in the window is demonstrably exposed and has explicit current `none_observed` coverage through the cutoff; event roots are never superseded and absence is never zero |
| Share of S3 and S6 decisions needing reconstruction, and their active attention | Plan/review `approval_record` rows directly referenced by a `packet_defect` tag with `fm_id = FM-10`, over all plan/review decision records, by gate, tier, role, and decision. Report unresolved and resolved defects separately using `resolves_tag_id`/resolution evidence. For the tagged numerator, report the record's attention-bucket distribution, including `unknown`; never invent minutes from buckets |
| "Deliberately not touched" items later shown correct | (Later, with R-O-8) needs a signal from a subsequent ticket touching the same code |
| Escalations per ticket from S4 | Count of `escalation` tags with `ref` in an S4 stage run, per ticket |
| Index entries found stale per ticket | `index_use` rows with `stale = true`, per ticket |
| Close survey | (Later, with R-S7-5) `ticket.close_survey`, reported as answered share and the answers |
| Share of stage runs passing on the first attempt, by stage and tier | Eligible top-level `stage_run` rows with `attempt = 1` and `outcome = pass`, over those with first-attempt outcome `pass`, `fail`, `infrastructure_failure`, `sandbox_violation`, or `aborted_budget`. Exclude and report separately `blocked`, `refused`, cancelled (`aborted_human`), child runs, utility runs, and every `stage_run` whose `run_kind` is not `task`. At S4 the unit is (`stage`, `plan_item`) and pass comes only from green task-validation checks (R-S4-5) |
| Context: factory completions and external outcomes per window | `factory_completed_at` counts draft PRs; `closed_at` separately counts manually observed merge/abandon outcomes; neither is labeled as the other |
| Context: cost per ticket, by stage and tier | Sum non-null `stage_run.cost`, child runs included, grouped by currency and reported separately as `provider_settled`, `runtime_estimate`, and `price_table_estimate`, plus the count of `unavailable` runs; never combine currencies or present estimates as settled cost |
| Context: non-structural touchpoints per ticket, by tier | `queue_item` rows of kinds `question`, `red_check`, and `escalation` per ticket (D29); `eligibility` is excluded as structural and `rubric_inspection` as a factory-health signal |
| Context: fix rounds per ticket | Count of S4 `stage_run` rows with `run_kind` `fix_round` per ticket, with the recipes that failed before each fix round; reported beside first-attempt reliability, never folded into it |
| Context: tool calls and tool-result bytes per stage run, by stage and tier | Count of `tool_call` rows and sum of `result_bytes` per stage run, with the inline share; an unavailable size is counted as unavailable, never estimated (R-I-17) |
