# 3. Stage interface

Part of the [Software Factory PRD](prd.md). The index holds the version, the reading rules, and the map from section numbers to files.

| # | Requirement | Cites | Version | Verified by |
|---|---|---|---|---|
| R-I-1 | The factory exposes one API and every client uses it: runner, list view, digest, and any later MCP server. Initial operations: advance a ticket; run a named stage; pause at a stable boundary; stop; get record/status; list and act on the queue; migrate a ticket to a reviewed manifest; record PR revision/outcome, production exposure/coverage, incident/control event and disposition; record an R-O-13 graduation decision; get measures; governed export, import, and purge. Later: sync an observed PR head, score runs, open a proposal, run a benchmark. Nothing else invokes an agent or writes the record, and the runner imports the stage interface and nothing inside a stage. | C7, C5, P10, P11, FM-19, FM-21 | Initial | API exclusivity, graduation-authority, and runner import-graph tests |
| R-I-2 | Each agent attempt is a fresh invocation. It receives the governed ticket artefacts named in the manifest for that stage, their hashes, the rubric file, and nothing from an earlier invocation's transcript or user-level runtime configuration. A rerun after a blocking question, failed S4 verification, or escalation learns the round and full recorded history from registered artefacts alone. Reconstructable means the input and execution envelope can be rebuilt; it does not mean a hosted model must return identical output. | C1, C3, C4, P4, P7, FM-21, FM-19 | Initial | Script test: the invocation envelope is reconstructable from the governed record alone |
| R-I-3 | Each stage run attaches only the MCP servers and tools the manifest lists for that stage and tier, and ignores user- or workspace-level runtime tools not in that list. Native write and shell tools are denied unless the stage role permits them. S4 writes only its R-I-14 worktree mount; S5 writes only its disposable build layers and governed evidence. No stage has a push-capable remote or credential. Agents request typed command recipes rather than shell strings. The resolved set is written before start. | C1, D8, P10, FM-05, FM-20, FM-23 | Initial | Manifest and sandbox tests for undeclared inherited tools, source writes, path and symlink escape, arbitrary shell, ambient credential access, and push |
| R-I-4 | The manifest names, per stage and tier, with a `default` entry used by the pilot: agent definition, skill, rubric, tool allowlist, budget, runtime adapter and exact package version, approved requested model, grader model, sandbox policy/image, toolchain, and for S2 the restatement model. Files are path plus content hash; software is immutable version or digest. Budgets are tokens and wall-clock seconds, never runtime-specific units (D5). Script-only stages carry null agent/model fields. An unresolved or unavailable entry fails closed; no adapter silently substitutes a runtime, model, tool, or image. S0 pins the resolved manifest hash on the ticket and every later run must match it; a human-approved manifest migration invalidates S1 onward and returns to `context`. | C6, C1, D5, D31, P2, P10, FM-17, FM-19, FM-25 | Initial | Manifest, migration and unavailable-model fixtures; schema test that budget keys are `tokens` and `wall_clock_seconds` only |
| R-I-6 | A stage run that exceeds its tier budget, or S4 whose cumulative executions exceed the per-ticket S4 budget, is stopped with outcome `aborted_budget` and the ticket moves to `escalated`. The item carries reasoning summary, registered outputs, current binding if one exists, and failure history. Wall clock is enforced live and runtime-settled tokens at each invocation boundary; totals are checked before every fresh S4 execution and child runs count against the parent. Stopped work remains isolated and the item names the last completed task, execution and verification count. Budget abort does not consume S4's verification quota but ends the loop immediately; a changed budget is plan-bound and requires migration/reapproval. | D14, P10, FM-19, FM-21 | Initial | Per-stage and cumulative-budget, child-count, outcome/state, and reapproval tests |
| R-I-8 | Stop terminates a running stage, records `aborted_human` with the reasoning summary and governed outputs so far, and moves the ticket to `escalated`. A pause request instead takes effect at the next stage or S4-attempt boundary (R-H-13). Stop is the only mid-invocation intervention and neither action injects steering text into a live model context. | C3, P10, P11, FM-19, FM-09 | Initial | Script test for stop and pause ordering |
| R-I-9 | A read-only MCP server exposes get record, list queue, get measures, and export, so the engineer's own agent sessions and the improvement agent can read the factory without touching it. | C5, P11, FM-17 | Later | Script test: no write operation is exposed |
| R-I-10 | The runner enforces the parallel ticket limit in section 8. A ticket beyond it waits at `intake` and the list view shows capacity wait from state/config with `blocked_on` null, not as a human wait. A higher value takes effect only when an R-O-13 graduation approval binds the passing report and exact configuration hash; editing the file alone is refused. | D28, P1, FM-09 | Initial | Capacity, unsigned-edit, stale-report, and approved-change tests |
| R-I-11 | Forbidden capabilities, tested over manifests, inherited runtime configuration, recipes, sandbox mounts, environment and credentials together: no GitHub merge, default-branch push, pull-request approval, Actions rerun, arbitrary network client, or arbitrary shell at any stage; source-tree write only at S4's worktree mount; S5 writes only disposable build layers and governed evidence; GitHub branch/PR write only in the trusted `pr_create`/`pr_update` outbox worker; Slack post only through the digest intent; no write capability at S1. A hidden capability fails the walking skeleton. | D4, C1, P10, FM-05, FM-18, FM-23 | Initial | Manifest and sandbox capability test |
| R-I-12 | Every artefact with a fixed section list (brief, criteria, plan, packet) fails on structure, before any judgment check runs, when a section is missing or empty, and for the plan when a table of R-S3-18 is missing a column or a required row, or a traceability rule of R-S3-19 fails. The section lists are the "Produces" paragraphs in section 4; a section marked `pending answer` by a run that ended `blocked` is exempt until the rerun. | P4, P9, FM-16 | Initial | Script test per artefact kind and per plan table |
| R-I-13 | A runtime adapter is pinned runner code outside `factory/`, one per runtime, the Cursor SDK adapter first. It takes the complete R-I-15 envelope, starts the sandbox, invokes the requested model, and returns the requested and resolved model, exact runtime/adapter versions, every available usage/cost/duration/outcome field, reasoning summary, and one governed `tool_call` row per call. Missing runtime fields remain null, except stage-run cost may be derived from final runtime-reported token totals under the approved price-table rule in 2.2; the adapter records cost basis, currency and table hash where applicable and never estimates tokens, duration, or per-tool-call usage. The record schema and stage behavior do not depend on the adapter, and an adapter upgrade must pass R-F-14. | C5, D5, D31, P7, FM-19, FM-21 | Initial | Adapter contract test with settled, runtime-estimate, price-table, null, and silent-fallback fixtures |
| R-I-14 | Every agent invocation and repository/build recipe runs inside an OS-enforced sandbox identified by immutable policy or image digest. S4 alone writes the isolated ticket worktree. S5 provisions separate clean base and head copy-on-write views over immutable lower layers, with isolated empty recipe-declared build-output, scratch and cache uppers; no upper-layer file is copied back, the layers are destroyed after governed evidence capture, and the runner rechecks the underlying commits and diff afterward. Other registered inputs are read-only. No host home, keychain, SSH agent, Docker socket, unrelated checkout, or ambient environment is visible. Direct egress is denied except the adapter's approved hosted-inference endpoint, stage-approved MCP proxy, and recipe-declared deterministic registry endpoints. `factory/` and the run database are outside the sandbox write boundary. | C1, D9, P10, FM-05, FM-20, FM-21, FM-23 | Initial | Escape suite covers paths, symlinks, subprocesses, environment, sockets, network, mounts, base/head isolation, source immutability, overlay disposal, and credentials on the pilot host |
| R-I-15 | The reconstructable invocation envelope records ordered input artefact ids/hashes and guard decisions; rubric/agent/skill hashes; manifest, trust-profile/trust-approval and recipe-set hashes; exact adapter/runtime/tool/MCP-server versions; requested/resolved model; sandbox/toolchain digests; base/head SHAs; data class, reviewer/approval subject where applicable, tool allowlist, and governed tool arguments/results used by the output. Provider request id is recorded where available. If a provider does not expose an immutable model build or a tool result cannot lawfully be retained, `replayability` is `best_effort` with that blind spot; it is never called exact replay. | C3, C4, C5, C6, P4, P7, FM-17, FM-21, FM-24 | Initial | Export/reconstruct, governance-binding, and unavailable-provider-field fixtures |
| R-I-16 | Commands are versioned typed recipes, never plan-authored shell. Each recipe has an id, executable digest or sandbox-image path, argument vector with typed placeholders, fixed working-directory role, permitted stages, timeout, expected exit codes, environment-name allowlist, network policy, and output-retention rule. No shell interpolation, command substitution, redirection, or untyped free text is accepted. Plans cite recipe ids and typed values; the runner validates and executes them. | C1, C6, P6, P10, FM-11, FM-20, FM-23 | Initial | Schema and adversarial tests for injection, undeclared executable, cwd escape, environment leak, timeout, and expected result |
