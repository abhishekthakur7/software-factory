# S4 Implementation

Section 4 of the [Software Factory PRD](prd.md), one file per stage. The index holds the version, the reading rules, the rubric-line conventions, and the map from section numbers to files.

S4 is automated from the initial version (D20): the factory runs the implementation through the primary runtime, one fresh invocation per plan-task attempt, under the D14 bounds, in a sandboxed isolated worktree on a ticket branch. Nothing is pushed until the engineer approves the packet at S6. The hand-off and hand-back fix what S5 and S6 need whoever produced the change, so an external implementer stays possible. Two runner-driven loops stay inside S4: a bounded fix round after a red machine-only S5 result (R-S4-9) and a validation-only rerun after a disjoint base advance (R-S5-14); each is a recorded run, never a hidden repair loop.

| R-S4-9 | Fix rounds. When an S5 pass ends red and every red result comes from the project's own lint or compile/type recipes as scoped by R-S5-10, or from a unit-test recipe that is green at base and red at head, and fewer than the section 8 number of fix rounds have run on the ticket, the runner returns the ticket to `implementing` without a queue item and starts one fresh S4 invocation with `run_kind` `fix_round`. A fix round may not delete or change a test that exists at base; a test this ticket added may change, every test-file change is recorded as a deviation and named in the packet's evidence table, and a round whose diff touches only test files is refused. **Rubric, S4.** R-S4-2: deterministic, deviation list present and well-formed; synthesis S4, original schema. R-S4-5: deterministic, typed task-validation recipes run by the runner; original, from the v0.5 review.

**Human touchpoint.** None during normal implementation. A stale-binding `red_check` requires refresh, send-back, or abandon; an escalation requires the cause-specific action in R-S4-6. Fix rounds and disjoint base advances need no human action and appear in the packet's evidence table.
